================================================================================
                           INFRAMIND FEATURE SPECIFICATIONS
================================================================================

InfraMind is a full-stack, AI-powered system architecture design platform. It allows users to write system descriptions in plain language and generates system architecture diagrams, user sequence flows, database schemas, REST APIs, deployment specifications, and download-ready project scaffolds.

This document describes all implemented features, system designs, APIs, state management, database schemas, routing, and custom interaction architectures in this project.

--------------------------------------------------------------------------------
1. TECHNOLOGY STACK
--------------------------------------------------------------------------------

Frontend (Client-side Module)
- Framework: React 18 (Vite build system)
- Routing: React Router v6 (BrowserRouter) with route guards, parameters extraction, and deep-linking (/workspace/:projectId)
- State Management: 
  - Zustand (useArchitectureStore.js) for local cache orchestration (minimizing database reads)
  - Custom React Context (AuthContext.jsx) for Firebase Authentication session persistence
- Visual Rendering: Mermaid.js rendered dynamically in the browser (via SVG parsing with Zoom/Pan controls)
- Styling: Vanilla CSS Modules (modular CSS scopes, zero TailwindCSS) for premium dark-themed custom aesthetics
- Scaffolding Compiler: JSZip (compiles entry stubs, README, routes, schemas, docker-compose in-browser into a ZIP)
- Exporting Engine: html2canvas + jsPDF (client-side PDF canvas rendering)
- Icons: lucide-react + SimpleIcons CDN (resolves technologies dynamically to brand-colored SVG icons)

Backend (Server-side Module)
- Runtime: Node.js + Express
- Database: Cloud Firestore (NoSQL, managed by Firebase Admin SDK)
- Authentication: Firebase Admin SDK (token verification middleware)
- API Endpoints: CRUD endpoints for user profiles, project histories, and public sharing links

3. API CONTRACT SPECIFICATIONS
--------------------------------------------------------------------------------
The backend exposes the following REST APIs:

| Method | Endpoint | Auth Required | Description |
| :--- | :--- | :--- | :--- |
| GET | /api/health | No | Health check, confirms server status and Firestore connectivity. |
| GET | /api/projects | Yes | Retrieves the current user's generated project list ordered by updatedAt desc. |
| GET | /api/projects/:projectId/history | Yes | Fetches the full chat and iterative history for a specific project. |
| POST | /api/projects/history | Yes | Saves a new chat history entry (generates project if projectId is null). |
| POST | /api/projects/:projectId/share | Yes | Sets a project public status, creates share records with dynamic owner profile bindings. |
| DELETE | /api/projects/:projectId/share | Yes | Deletes public share link, resetting shareId and isPublic status. |
| GET | /api/profile | Yes | Fetches user profile settings. |
| POST | /api/profile | Yes | Saves profile settings, enforcing unique, lowercase usernames. |
| GET | /api/public/:shareId | No | Resolves public read request, returns architecture data along with creator profile details. |

All authenticated endpoints require a "Bearer <Firebase ID Token>" inside the Authorization header.

4. FIRESTORE DATABASE SCHEMAS
--------------------------------------------------------------------------------

1. Users Document (users/{uid})
{
  "profile": {
    "username": "string (lowercase, globally unique, alpha-numeric + underscore)",
    "name": "string",
    "photoUrl": "string (Cloudinary URL or Base64 fallback data string)",
    "githubUrl": "string",
    "twitterUrl": "string",
    "linkedinUrl": "string"
  }
}

2. User Projects Subcollection (users/{uid}/projects/{projectId})
{
  "title": "string (project title)",
  "summary": "string (project summary explanation)",
  "layersCount": "number (amount of items in tech stack)",
  "apisCount": "number (amount of routes defined)",
  "shareId": "string | null (public share ID reference)",
  "isPublic": "boolean",
  "updatedAt": "timestamp (server timestamp)"
}

3. Chat History Subcollection (users/{uid}/projects/{projectId}/chatHistory/{messageId})
{
  "prompt": "string (the user prompt / modification description)",
  "geminiResponse": "object (conforming to the Gemini response JSON schema)",
  "timestamp": "timestamp"
}

4. Shares Collection (shares/{shareId})
{
  "shareId": "string (unique hex string)",
  "ownerId": "string (references users/{uid})",
  "projectId": "string",
  "title": "string",
  "summary": "string",
  "architecture": "object (snapshot of Gemini JSON response)",
  "createdAt": "timestamp"
}

5. KEY COMPONENT IMPLEMENTATIONS & FIXES
--------------------------------------------------------------------------------

SPA Routing on Vercel
- Standardized SPA catch-all rewrites inside "vercel.json" configurations:
  {
    "rewrites": [
      { "source": "/:path*", "destination": "/index.html" }
    ]
  }
- Placed in both /client/vercel.json and /vercel.json (project root) to handle route mapping successfully whether the builder builds from the root directory or client subdirectory.

Environment Variable Consolidation
- Cleaned and consolidated frontend endpoint configuration under a single Vite-native environment variable:
  import.meta.env.VITE_API_BASE_URL
- Replaced all old "process.env.REACT_APP_API_BASE_URL" usages in hooks and Zustand stores to prevent runtime connection mismatches when deployed.
- Configured VITE_API_BASE_URL=http://localhost:5000/api in client/.env for development.

Mermaid Diagram Scaling & Zooming
- Initial scaling is derived from container height with a 40px safety padding (vertical layout protection) to prevent nodes from overflowing or clipping.
- Minimum scale (minScale) is clamped to initialScale, which allows zooming in but locks zooming out beyond the initial layout bounds, keeping the diagram readable.

Diagram Click/Tap Interception Resolution
- The zoom/pan wrapper (react-zoom-pan-pinch) intercepts touch and drag events, which was blocking standard "click" events on SVG node elements inside the TransformComponent canvas.
- Resolved by refactoring the click handler to Pointer Events (pointerdown & pointerup) with distance and speed checks (less than 5px drag drift and under 300ms duration). This reliably detects clicks/taps on nodes and triggers details selection while preserving normal pan/zoom mechanics.

Mermaid Syntax Pre-render Sanitizer
- AI generation frequently outputs invalid Mermaid syntax, such as casing issues (SubGraph / End) and unquoted titles containing spaces (e.g. subgraph Backend CI/CD).
- Resolved by implementing a pre-render parser mapping lines to valid formats before calling the rendering engine:
  - Casing fixes: "SubGraph" -> "subgraph", "End" -> "end"
  - Unquoted titles: automatically wraps space-separated subgraph titles in quotes (e.g., subgraph "Backend CI/CD")
- Gemini system prompts were also optimized to avoid using subgraphs entirely, opting for flat diagram generation to prevent syntax parsing bugs.

AI Repair & Fallback Loops
- Direct client-side calls to the Gemini API bypass backend proxies to leverage user keys.
- Utilizes regular expressions and brace-matching scopes in "gemini.js" to extract JSON text.
- Implements a zero-temperature repair prompt which automatically runs to fix malformed brackets or syntax if parsing fails initially.
- User profile picture uploads fallback gracefully to Firestore Base64 strings if the Cloudinary API upload presets fail or timeout.

Firestore Security Protocol
- Firestore rules isolate each user's space under their auth UID:
  match /users/{userId}/{document=**} {
    allow read, write: if request.auth != null && request.auth.uid == userId;
  }
- Public read access for share links is handled via the server's Firebase Admin SDK (root credentials) rather than directly opening up shares in the Firestore rules, preventing clients from scraping or harvesting shared blueprints.
